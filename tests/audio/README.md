# Audio driver and global service regression

```sh
sh tests/audio/run.sh
```

The binaries use ASan/UBSan and production C source. No dependencies are installed and no hardware is accessed. Set `AETHER_TEST_OUTPUT` to an absolute private directory when validating concurrently.

Write diagnostics cache mutex-wait and selected-output durations separately,
including timeout/failure peaks for the handle lifetime. A deterministic test
injects 17ms lock acquisition, 23/31ms output work and a 1s mutex timeout, then
checks retained maxima/errors and reads the snapshot while the audio mutex is
already held. This validates accounting and getter lock independence, not
physical DMA underruns or S31 scheduling latency.

`audio_test.c` executes the AC101S variant's shared session, master-volume, external-transport and route logic. Hardware doubles preserve codec mute across closes and assert PA ordering. Coverage includes 100 start/stop cycles, partial-open/configuration failure rollback, validation/mutex timeout, requested×master local volume, true zero-volume mute with PA low across restarts, failed-volume restoration, failed external-route startup restoring the prior local session, source-preserving bounded PCM copy/scaling, external zero PCM at mute, 1-second write deadline, disconnected transport errors retaining the external route, and explicit manual return to speaker. The existing external gain curve is checked; no headphone hardware volume is additionally applied by this test.

The local speaker now maps the combined logical level to a maximum codec volume of **70 on the previous 0–100 scale**, rounding upward so a previously nonzero combined level stays nonzero. All 10,201 legal stream/master pairs run through the real live-volume API, checking that bound, zero mute/PA gating and unchanged logical getters. Another 100 full-volume restarts and Bluetooth round trips verify that saved logical 100 cannot bypass the speaker limit while external full-scale PCM stays bit-exact. This constrains codec volume; it does not measure speaker watts or acoustic loudness.

`ac101s_register_test.c` runs the real AC101S register driver against an I²C register double. It checks the 0x33 address, initialization rollback, 16-bit Philips I²S, ADC/DAC and microphone-bias transitions, 100 playback/capture pairs, the -12 dB line-output ceiling and its upper-level transition, readback after ignored writes, and best-effort shutdown with retry after an I²C fault.

`system_test.c` executes the production global service's actual `service_once()` work body using deterministic scheduling and radio/driver/NVS doubles. It covers task-init failure/retry, loading persisted mute/unmute, 250ms driver retry with tick wrap, failed getters preserving confirmed snapshots, a newer volume request arriving during application, Bluetooth disconnect retaining external output without automatic speaker playback, reconnect retaining the selected route, media-time persistence deferral, 1-second persistence failure backoff, a new setting arriving during NVS commit, bounded remote-event processing and ignoring peer absolute volume for the software master. It does not simulate actual Bluedroid/SMP scheduling; the separate Bluetooth suite runs the production radio manager on host threads.

`route_test.c` runs the actual codec route/session/write/stop functions on real pthreads with timed mutexes. A 2-second delayed transport-start ACK runs concurrently with the media writer: handover must not turn the original 1-second mutex wait into a playback error. Only a route epoch crossing extends the total I/O lock wait to at most 4.5 seconds; unrelated contention still times out at 1 second. STOP during handover cancels transport startup within the existing 1-second stop deadline, including an artificial START publication after the first STOP signal. The session serial prevents a late ACK or failed-route rollback from reopening either output after STOP. These are host scheduling bounds, not measured S31 audio latency. The system suite also rejects `DISCONNECTING`/`STOPPING` peers as routes and verifies unavailable-route retries do not repeatedly reprogram unchanged gain or toggle PA.

The route suite also pauses STOP after its serial publication and initial NULL cancellation snapshot, but before its first mutex take. A competing route then acquires the mutex and captures that same new serial. The unfinished-STOP completion gate must reject the route without even entering sink startup or rolling back to speaker; STOP then completes normally. This covers both orders of the handshake/STOP race.

`capture_test.c` executes the production microphone API. One hundred capture sessions run with the external output selected, but use only the local ADC: the DAC remains muted, PA remains low, neither external sink callback runs, master-volume changes do not touch the live codec, and playback start/write plus output changes are excluded. A stale playback STOP does not close capture; a stale capture STOP does not close a later speaker or external playback. Every capture setup stage has rollback coverage, including PA and codec setup failure. A failed close retains the reservation, disables further capture reads and permits safe cleanup retry.

Capture reads check actual I2S byte counts rather than the installed codec adapter's status alone. Tests cover whole-block assembly from aligned short reads, a single 1-second budget shared by mutex acquisition and DMA reads, partial timeout, zero/misaligned byte counts, invalid buffers and unsupported sample rates. These are deterministic host driver doubles, not microphone acoustic measurements. The transport is 48kHz PCM16 stereo with the mono ADC in both slots; the recorder may take slot0. On the AC101S, the driver copies slot 0 into both channels before returning board PCM. USB microphone PCM retains both transport channels.

USB route coverage adds20 live speaker→USB→Bluetooth→USB transitions with actual source-preserving PCM checks, one software master/stream gain, immediate USB-unplug fallback to the capped local speaker, and failed-start/stop ownership retention. A STOP published during USB cleanup cannot reopen the speaker or continue that stream. USB microphone tests pass exact normalized48kHz PCM16 stereo through the capture API, verify remaining read budgets, reject playback/input changes during capture, retain a failed-stop owner, and recover board input only on an explicit selection. The service checks cached USB availability, bounded wrappers and requested/applied state; removal preserves an unavailable USB microphone selection so asynchronous recorder preparation cannot silently substitute the board microphone. Output and input choices remain session-local; volume persistence is unchanged.

Real codec electrical behavior, PSRAM/I2S DMA pressure, headset gain/latency and long-duration concurrent playback remain device acceptance work. Host mute/PA assertions are not an audible-output measurement. The USB class backend and its official-driver adaptation have a separate `tests/usb_audio` suite.
