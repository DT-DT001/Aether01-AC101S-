# 多媒体运行范围与实机验收

本文记录媒体会话及实机验收的方法，目标为 ESP32-S31 和 ESP-IDF 6.1。媒体性能以对应硬件版本的实测为准。

## 支持范围

| 项目 | 当前范围 | 明确限制 |
|---|---|---|
| 视频容器 | 原始MJPG/MJPEG、经典单RIFF MJPEG-AVI的第一路视频流；识别LIST/movi/rec、块边界和奇数填充 | 无AVI音轨播放、进度跳转/索引使用、OpenDML/AVIX多RIFF续段或MP4/H.264解码 |
| 视频图像 | S31硬件baseline JPEG转RGB565；宽高各不超过480且各为16的整数倍，单压缩帧不超过512KiB | 渐进式及其他非baseline JPEG不支持；尺寸上限不表示该尺寸必达30FPS |
| 视频节拍 | 自动读取AVI主头`avih`微秒节拍，支持25/29.97/30 FPS等1–30FPS源；raw自动24FPS；可选10/15/24/30目标覆盖 | raw无原始时间信息；自动模式遇到超出1–30FPS的节拍明确失败；UI显示的目标整数不丢弃29.97内部节拍 |
| NES | NTSC iNES 1.0，ROM不超过8MiB；Mapper限内置Nofrendo核心实现 | 拒绝PAL-only、NES 2.0和不支持Mapper；通过少量游戏不代表全ROM/Mapper兼容 |
| NES输入/音频 | 两点触摸，一指提供方向及斜向、另一指提供A或B；SELECT/START、暂停/继续、重启、退出 | 两触点不能同时满足所有独立三指组合；实际坐标、手感、声音及游戏兼容性仍须实机测试 |
| 小说与文件名 | FatFS UTF-8 API/CP936；UTF-8、GBK、UTF-16LE/BE流式转码，自动/手动选择，缺字/坏码诊断，源字节书签 | 无BOM识别不能保证无歧义；GB18030四字节扩展/UTF-32不支持；超出提供字体的码点仍可能缺字 |
| 局部刷新/TE | 渲染前2×2窗口对齐，每轮首块等待新TE，超时降级/冷却/取消 | 不提高40MHz QSPI，单次TE起传不保证整帧无撕裂；详见[显示运行边界](display-runtime.zh_CN.md) |

音乐、阅读器及其余应用的格式范围见[工程说明](../../README.md)，本轮视频和NES修复不扩大其他文件格式范围。

## 本轮修复与错误行为

- 视频按RIFF块边界取帧，跳过头部缩略图、音频、索引和其他流的JPEG样式字节，防止错帧。截断、越界、空文件和不支持的图像明确进入错误状态。
- 视频用微秒时钟安排节拍，避免整数毫秒与固定24FPS拖慢25/30FPS素材；暂停不计入活动播放时长，切速、暂停和停止使用短等待检查。负载过高时不积累无限追帧突发，记录超时帧。
- 暂停中拔卡按错误结束并释放文件租约；停止/退出等待硬件及回调结束。输出缓冲发布、保留帧释放和重复启动使用同一状态锁保护，避免退出后使用旧内存。
- NES修正定时tick与有界追帧，避免追赶负载长期占用任务。跳过图像只省去该画面的生成，每个实际模拟帧仍推进APU与音频；codec失效后继续推进静音模拟并累计音频错误，避免游戏音频状态停滞。
- NES暂停不推进模拟，关闭PA，恢复时重新开启音频；输入故障取消按住状态并退避，唤醒手势消费到抬手，停止/拔卡优先退出。单指斜向与另一指动作键的组合已纳入主机回归。
- NES每次启动重置手柄注册表和按键状态，修复第17次进入时注册表越界及上一ROM粘键。真实核心测试进一步发现并修复PPU上下文复制时空页/内部nametable页的重定位错误、像素复制的有符号移位溢出，以及CPU未对齐字读取和跨非连续bank取字；不改变CPU/PPU周期或Mapper算法。
- 三缓冲采用保留最新待显示帧的方式限制排队延迟。交给LVGL前清除可变图像描述符的旧缓存，退出先解除图片引用，再由停止屏障结束生产者和释放保留帧。
- CST9220按`D204`读取的固件项目ID选择报告协议：已确认的`0x542F`使用`D109`且不发ACK；`0x6854`及未知项目保留`D101`并在每次成功读取后严格发送`D0 00 AB`。修复旧代码固定混用`D109 + ACK`；空帧、释放和坏帧仍按当前协议确认，I²C读写错误继续上报，不按失败结果猜测切换协议。启动日志包含项目ID、报告页及ACK策略，唤醒恢复对应报告页。
- CST9220一次读取15字节，按第6字节（从0计）的`AB`标记及第二点偏移7解析；状态6/7均表示有效按下，保留0–15的四位tracking ID。最多输出两点并保持面板坐标边界保护；触点数量上限不再被误用为ID上限。NES归还GUI触摸时，原来仍按住的手势被消费到松手，防止退出动作穿透到下一页面。
- 修复滑动/长按被16ms轮询打断成点击：ACK回声、全零或缺少有效标记的轮询表示无新快照，不再清除物理按住状态；`get_xy`只读取缓存，不消费触点。有效标记下的记录数与status决定释放，首字节0仍可能是ID0释放记录，同时另一触点仍按住，不能提前把整包当作空帧。
- 传输错误仍原样上报，由GUI/NES取消逻辑按压并消费被中断的完整手势至真实松手；读错误保留物理缓存，避免恢复时无新帧被误认为已松手。有效释放即使ACK失败也先更新物理缓存，避免下一空轮询粘键。有效报告中active坐标越界返回错误，不把坏点过滤成成功的全松手；同包明确释放的ID仍从旧缓存移除，其余旧状态保留。
- 书签提交失败后保留待保存内容并退避重试，不再因入队成功就丢弃失败提交。待保存内容在PSRAM中合并，离开后重开书籍优先恢复RAM中的最新位置；多本书待保存缓存可增长，阅读进度显示待保存状态。
- 曲库刷新不再取消已经排队的切歌，也不会把旧索引解释为新列表中的另一首歌。播放器大路径搜索移出禁中断临界区；刷新遇到忙碌或内存不足保留原曲库及其索引，忙碌解除后自动重试，失败的指定歌曲请求保留到后续重试。
- 阅读器保留源文件，不全书加载或生成替代文件；每块转码结果附源offset映射，字号重排、上一页、100%跳尾和旧书签继续使用原文件字节。回扫用32KiB UTF-8输出覆盖16KiB源跨度，避免GBK/UTF-16膨胀后回到空页。普通已知边界翻页不反扫；任意GBK定位/转码可因离页/拔卡取消，文件和两块PSRAM缓冲由IO结果生命周期释放。顶部编码选择按书保存，v1数据按自动编码兼容读取。
- CO5300窗口在INVALIDATE_AREA阶段对齐，保证实际渲染像素和QSPI窗口一致；TE只同步每轮首块，不对每个40行块重复等待。无TE采用35ms预算和250ms冷却降级，唤醒/取消清除旧边沿许可；控制器限制、统计口径和吞吐下限见[显示窗口与TE](display-runtime.zh_CN.md)，不将初始化成功或主机同步用例当作无撕裂实测。

电源设置、工具设置、阅读书签和音乐偏好在音乐/视频/NES启动或运行期间延迟NVS写入，相关媒体暂停、停止或故障结束后再提交；不会为保存设置而停止媒体。排队的下一首也纳入音乐偏好的延迟条件。该策略依据媒体状态快照及guard回调作调度规避，**不是跨任务事务互斥**，不能据此证明状态检查后绝无并发启动或实机音频中断。未提交项仍在RAM，硬断电可能丢失；需要持久保存时应暂停/停止媒体并确认待保存状态清除。

CST9220协议依据[乐鑫官方v0.1.1说明](https://components.espressif.com/components/espressif/esp_lcd_touch_cst9220/versions/0.1.1/readme)及[对应版本源码](https://github.com/espressif/esp-iot-solution/blob/8eee17c20da66048faa20c683ffeb80bfa85d723/components/display/lcd_touch/esp_lcd_touch_cst9220/esp_lcd_touch_cst9220.c)。720b及本轮62ec均记录项目`0x6C76`的current / `D101 / D000=AB`；f80之后用户确认拖动正常，本轮62ec确认原小说正文/菜单正常。双点、长按、反复唤醒和所有操作仍按对应版本逐项验收。

## 指标如何解读

| 指标 | 实际含义 | 不能据此推断 |
|---|---|---|
| 视频`actual_fps_x100` / 日志`video produced` | 生产任务回调完成后的平均产帧率，数值除100为FPS；排除暂停时间 | 画面已经传到屏幕、每帧均可见或面板扫描率 |
| `source_fps_x100`、目标`fps` | AVI主头节拍与当前生效目标；目标整数四舍五入显示 | 原始MJPEG的真实拍摄帧率，或目标已达成 |
| `read_us/decode_us/callback_us` | 最近一帧读取、解码和回调耗时；`late_frames`为超过目标期限的累计帧数 | 全部帧的最大值/分位数；每10秒记录的最近值不是完整逐帧采样 |
| NES `emulation_fps_x100` / `emulated` | 实际执行模拟帧的速率；按运行采样窗口更新 | 生成了同样多画面，或LCD显示了同样多唯一帧 |
| NES `render_fps_x100` / `produced` | 核心生成并提交回调的画面速率；`skipped_frames`累计只模拟而未生成的画面 | 跳帧等同游戏逻辑或APU停顿 |
| 三缓冲`received/presented/replaced`、`queue_delay_us` | 成功复制接收、设置LVGL图片源、覆盖尚未交给LVGL的等待帧，以及复制接收至交给LVGL的等待时间 | 完整LCD掉帧数、输入至可见响应时长；锁竞争未接收的帧不计入`replaced` |
| LCD `refresh_fps_x100` / `lcd_refresh` | 最后一个LVGL flush区域的QSPI传输完成后计一次刷新；数字除100为FPS，快照字段`max_refresh_gap_us`描述完成之间的最大间隔 | 面板扫描/TE频率或唯一媒体帧；状态文字等局部更新也可形成刷新轮次 |

LCD完成统计与媒体生产统计采用不同采样窗口，短时读数无需相等。保持静态、暂停或息屏时刷新数减少也不表示故障。实际可见帧、撕裂、色序与操作响应可用带帧号素材、高速相机或硬件测量交叉验证。

- `tests/mjpeg_runtime/run.sh`：9组实际生产worker回归，合法baseline JPEG及经典AVI、25/29.97/30节拍、raw24、切速、暂停拔卡、解码时停止/释放、分配/引擎/解码故障，以及30轮保留帧释放重启。
- `tests/nes_runtime/run.sh`：6组ASan/UBSan回归。可控替身覆盖生产循环/平台层的追帧、跳帧音频、输入组合、故障退避、停止/拔卡及ROM/配置错误；CPU辅助测试覆盖未对齐、零页/16位回绕和分配于不同内存块的bank跨界。另用自行生成的原创NROM运行真实CPU、PPU、APU、Mapper 0、事件及视频核心，验证变化的画面与方波、暂停/重置、101次启动时清除旧按键，以及不支持Mapper失败后再次正常启动；OSD和定时采用替身。此夹具不证明其他Mapper或实际游戏兼容。
- `tests/frames/run.sh`及显示指标回归：应用三缓冲/缓存失效/回滚和LCD完成回调语义，不能模拟真实DMA、PSRAM带宽、面板扫描或全部SMP调度。
- `components/cst9220/test_host/run.sh`：实际驱动的legacy/current/未知项目协议、ACK长度与错误上报、双点/status6/7/四位ID、释放与坏帧、坐标边界，以及有/无RST的唤醒报告页恢复。新增含实机`0x6C76`项目的按下→128次无新帧→移动→单点/全释放、ID0释放、读错误保留物理按压、ACK失败仍发布释放及坏active坐标错误路径；`tests/touch/run.sh`覆盖GUI取消/退避、错误后消费完整手势及NES归还触摸。
- `python3 tests/touch_lvgl/build_run.py`：真实LVGL指针轮询、命中和部件事件的5组回归，覆盖100ms按住无提前点击、滑条拖动、列表滚动不点击子项、通信错误恢复后消费到松手及100次点击/堆检查。使用持续物理触点替身驱动生产adapter，不直接注入CLICKED；CST报文由上述独立驱动回归覆盖，硬件I²C与触摸坐标精度未模拟。见[测试说明](../../tests/touch_lvgl/README.md)。
- `tests/reader_io/run.sh`：生产书签队列饱和/合并/序号回绕、提交失败保留与退避、RAM重开恢复、三类媒体运行期间延迟提交，以及40本书的缓存增长。`tests/tools/run.sh`同时覆盖实际工具worker的媒体忙碌延迟保存、合并和失败重试。
- `tests/player/run.sh`：实际音乐worker、WAV/MP3解码、切歌/曲库刷新顺序、排队下一曲与其他媒体运行时延迟写Flash。`python3 tests/reader_ui/build_run.py`使用真实LVGL及工程字体，覆盖阅读/音乐操作和曲库busy/OOM后的旧索引保留及忙碌自动重试；硬件接口由替身提供。

测试命令和边界见[主机测试说明](../../tests/README.md)。这些证据支持软件分支和资源清理的正确性，不构成实际S31吞吐、音质或所有ROM兼容的结论。

## 建议的可量化实机用例

以下时长、次数和预算是建议验收条件，尚未达到或测量；测试结果应记录素材、TF型号/速度、供电、电池温度、板号、固件哈希和匹配ELF。完整电气/外设验收另见[设备验收表](acceptance.zh_CN.md)。

| 用例 | 建议执行量 | 记录与判定 |
|---|---|---|
| 原生视频速度 | 带连续帧号及秒标的25/29.97/30FPS AVI，各240×240与480×480；每份播放10分钟，前2秒不计稳态 | 记录源节拍、producer、LCD完成、late/replaced、读/解码/回调采样及最大刷新间隔；用外部时基检查10分钟播放时长。若声称该素材实时播放，建议稳态producer与目标偏差不超过5%，并外测实际可见唯一帧与长间隔；达不到就保留素材限制，不能以目标设置代替通过 |
| 视频控制与异常 | raw24、AVI自动及手动档各测试；暂停/继续/停止/重播100轮；播放、暂停、启动中拔卡各20轮 | 暂停不计活动时长，不突发追帧；拔卡进入错误或明确停止、租约排空且卸载断电，可重插重播。记录请求至状态改变、停止完成和卸载耗时，不能永久等待或出现退出后旧回调 |
| 格式边界 | 空文件、截断、渐进式JPEG、非16对齐尺寸、超大帧、音轨假JPEG、MP4、AVIX续段、自动超30FPS | 每份应有可解释的拒绝/受限行为，返回、重选与后续正常播放仍有效；AVI音轨不作为已支持功能验收 |
| NES游戏与音频 | 每种实际需要的Mapper选代表性NTSC iNES1.0 ROM，逐个运行30分钟；覆盖SRAM存档及无音频故障恢复 | 记录ROM哈希、Mapper、模拟/生成/LCD速率、skipped/audio/input错误。观察计时/速度、音高、噪声与跳帧时声音连续性；用游戏自身计时或已知基准核对模拟速度，不将60Hz目标当测量值 |
| NES输入/生命周期 | 上下左右、四个斜向分别加A或B，各20次；SELECT/START、暂停/恢复/重启/退出各100轮，期间息屏唤醒与拔卡 | 无粘键、唤醒穿透、退出后触摸占用或存档损坏；记录输入到可见响应，建议普通按钮p95不超过150ms、最大不超过500ms，实际接受预算需结合素材/负载确认 |
| 混合负载与资源 | 视频↔NES↔音乐↔阅读/目录100轮，包含启动即返回及100次息屏唤醒；随后24小时混合负载，再72小时长稳 | 0次异常复位/WDT/堆损坏/永久卡死；每分钟记录堆、最大连续块、最低栈、错误、温度及帧指标。预热后对比每轮回收基线，不能有持续泄漏趋势；缓存及保留缓冲的固定占用需与泄漏区分 |

高分位延迟或逐帧耗时需要足够密度的时间戳/外部采样；现有10秒性能日志中的最近一帧不能冒充完整的p95/p99。对发生的大间隔保留时间点和前后日志，区分SD读取、JPEG、LVGL交接、LCD完成及NES跳帧，以实测瓶颈决定下一轮优化。
