# 显示局部窗口、TE同步与验证边界

更新日期：2026-11-03。目标为ESP32-S31、现有ESP-IDF 6.1，屏幕为480×480 CO5300AF，GPIO8接TE，当前QSPI为48MHz（前版40MHz）。触摸与绘制周期8ms，LVGL软件tick2ms。PSRAM XIP已在设备上启用，用户确认明显顺滑；固定DMA镜像传输也已完成下述有限设备验收。以下区分当前源码与设备验收，不代表所有场景无撕裂或固定FPS；最终镜像以同次构建记录为准。

## 字体变斜与局部刷新窗口

此前代码未给`esp_lvgl_port`配置`rounder_cb`，LVGL可按按钮、文字等脏区生成奇数起点或奇数宽高，CO5300驱动又直接把该窗口和对应像素发给面板。这违反控制器的地址限制，能解释“初始正常，点击后局部文字变斜或显示损坏”的现象。已经确认的是软件窗口不符合手册；是否解释本板全部异常，仍须烧录后与信号质量、供电和时序一起复测，不能单凭文字外观归咎于字库。

[CO5300原厂手册，乐鑫托管](https://dl.espressif.com/AE/esp-iot-solution/CO5300_Datasheet_V0.00.pdf)第159页CASET、161页RASET要求起始地址以及区域长度按2对齐。现在在LVGL的`INVALIDATE_AREA`阶段向外扩展：起点取偶数、包含式终点取奇数，保证宽高均为偶数。扩展发生在渲染前，像素缓冲与发送窗口保持一致；不能在flush时单独放大窗口并继续发送原缓冲。

本机LVGL 9.5的`get_max_row()`也调用该对齐事件，因此窄区域按缓冲容量切块时，分块行数仍符合偶数要求。当前源码的两块PSRAM绘图缓冲各容纳480×20个RGB565像素，合计38,400字节；满宽时为20行，窄区域的实际分块高度由LVGL计算。生产配置的stride对齐为1，发送的RGB565行宽与窗口宽度一致。

## PSRAM XIP与固定DMA镜像

ESP32-S31已开启`CONFIG_SPIRAM_XIP_FROM_PSRAM`，应用`.text`和`.rodata`在启动时由Flash复制到PSRAM。当前链接布局约占6.44MiB外部RAM，后续固件增减代码或资源时占用也会变化。用户已确认开启XIP后操作明显顺滑；这项反馈不等于定量帧率或长期稳定性验收，也没有取消媒体运行期间延后NVS提交的策略。

当前源码把双20行绘图缓冲移到PSRAM，并在显示初始化时预留一个64字节对齐、19,200字节的`INTERNAL|DMA|8BIT`镜像。每块像素先复制到镜像，再由原port在镜像上执行一次RGB565字节交换并提交QSPI；PSRAM渲染源保持不变。镜像只能在上一笔DMA完成后复用，不依赖每笔传输临时分配bounce缓冲。镜像预留失败时显示初始化失败，不能悄悄退回压力下的临时分配路径。

仅按像素缓冲计算，内部占用从双20行的38,400字节变为单镜像19,200字节，预计净省19,200字节（18.75KiB）；这不是已测得的空闲堆增量，控制对象和分配开销仍需另计。DMA镜像方案本次有限设备验收已完成，证据和未覆盖项见下文；XIP与镜像传输的反馈分别记录。

## TE如何进入传输链路

原实现仅将GPIO8配置为输入且关闭GPIO中断，没有等待TE；发出TE开启命令不等于MCU使用了TE。模块规格书第8页将FPC23定义为TE输出。本轮明确发送`35h`参数`00`与`44h`参数`0000`，选择垂直消隐信号，并监听上升沿；模式与极性依据同一原厂手册的TE章节。

运行顺序为：

1. LVGL一次实际渲染开始时，`RENDER_START`只标记本轮尚未同步，不阻塞渲染。
2. 第一块像素渲染完成，进入`FLUSH_START`时，LVGL任务等待一个新的TE上升沿，再交给原有port/QSPI发送回调。
3. GPIO ISR只记录边沿、周期并唤醒等待者，不调用LVGL，也不等待面板或DMA。信号量发布在短状态锁之外，通过在途发布计数保护销毁时的资源。
4. 同轮剩余分块直接发送，不逐个20行块再等TE。多个脏区也共用这一轮的首块同步。
5. QSPI完成后继续发布flush-ready与LCD完成统计。当前固定镜像路径同时解除镜像的DMA占用；TE接入仍只控制首块的发送时机，不提前归还或复用在途缓冲。

等待前记录边沿序号并清除旧信号，不能拿上次刷新或息屏前的TE许可启动新传输。无脏区就不等TE。

## 超时、休眠和取消

- 首块等待预算为35ms，实际阻塞还受RTOS tick和任务调度粒度影响。没有TE时允许本轮退化为非同步刷新，界面不会永久等信号。
- 缺失TE后采用250ms冷却旁路，避免每次刷新都额外耗掉一个完整超时；发现边沿恢复后重新等待新的边沿并恢复同步。
- 普通息屏/唤醒在DCS命令前取消当前等待，唤醒后的下一轮仍须等新的TE。取消会清除旧周期样本，避免把睡眠间隔当成面板周期。原有息屏逻辑仍负责暂停/恢复LVGL刷新和保留面板/触摸供电。
- 同时只允许一个TE等待者。删除显示资源前必须先停止LVGL生产者；组件会取消等待、移除GPIO处理器并有界排空已进入的发布者后再释放信号量。
- GPIO或ISR初始化失败会报告不可用并保留显示降级路径；成功安装中断不代表已经收到真实TE。

## 状态页和日志的含义

设备状态页现在只显示TE不可用、等待有效信号，或已观察的TE频率，不再显示累计同步/超时次数。频率由最近两个GPIO上升沿间隔换算，刚恢复后的首个边沿还没有完整周期样本；它不是应用产帧率或LCD唯一可见帧率。

按用户要求，`display_sync`日志只保留以下频率信息，绘制期间最多每10秒输出一次：

| 字段 | 含义 |
|---|---|
| `TE GPIO8` | 实际信号输入引脚 |
| `frequency=59.64 Hz` | 由实测边沿周期换算；该数值来自本轮日志，随采样略有变化 |

无边沿时仍提示非同步fallback。内部诊断API保留协议所需时序和计数，不在日常日志或状态页输出累计次数，也不将其保存到Flash。上面的计数验收记录是历史证据。TE、视频producer、NES模拟/生成帧、LVGL交帧和LCD传输完成是不同层的指标。

## 48MHz与全屏刷新的实际限制

480×480 RGB565为460,800字节；当前48MHz四线QSPI仅像素负载的理论最低发送时间为19.20ms，前版40MHz为23.04ms，均未计算命令、渲染、分块和调度开销。若面板扫描为60Hz，一次扫描约16.7ms，完整传输仍超过它。因此只在帧开始等一次TE不能保证所有全屏更新都无撕裂，低于最大尺寸的局部区域也应按实际传输位置与耗时验证。

QSPI已经由40MHz提高到48MHz，未使用80MHz，也没有写入未经模组厂验证的面板30Hz/振荡器/扫描寄存器。下一步应测GPIO8周期、TE至首个QSPI事务的延迟，以及首末传输总耗时，再结合模组厂资料决定是否调整扫描或传输策略。

建议在本轮匹配镜像上记录：连续滚动中文和列表、快速点击更新、横竖条移动、带帧号视频、NES动态画面，分别观察首次全屏与后续局部更新。至少循环100次息屏/唤醒并验证TE重新同步；使用安全故障夹具模拟TE缺失时，检查超时降级和触摸/返回操作仍可恢复。用逻辑分析仪对照TE、CS、CLK，外部拍摄核对可见撕裂和字体是否仍变形。没有这些实机记录，不能宣称无撕裂或给出硬件持续FPS。

## 主机验证

独立入口：

```sh
sh tests/display_te/run.sh
```

前半段6组生产TE逻辑在ASan/UBSan下检查新旧边沿、共享ISR、超时冷却、恢复、取消、并发等待、在途ISR/销毁重叠及分配/GPIO/ISR失败清理。后半段使用已有真实LVGL对象验证3组刷新语义：双40行缓冲的全屏12次传输只等一次TE，1000个奇数/小/裁剪区域及窄高区域分块保持地址/stride/像素长度一致，以及超时/取消/恢复不遗失flush-ready。

真实LVGL部分也可单独运行：

```sh
python3 tests/display_te/run_lvgl.py
```

它复用`build/host_reader_ui`的原生LVGL对象；缺少缓存时先运行`python3 tests/reader_ui/build_run.py`。GPIO、RTOS或TE等待接口按测试层分别替换，缓存LVGL对象未启用ASan，另做LVGL堆完整性检查。主机回归证明软件窗口和同步分支，不证明板上信号、供电、扫描相位或无撕裂。详见[测试说明](../../tests/display_te/README.md)。

固定DMA镜像另有`python3 tests/display_te/run_staged_lvgl.py`，覆盖真实LVGL分块、复制/字节交换所有权及延迟完成等路径，说明见[显示完成与DMA等待回归](../../tests/display_metrics/README.md)。主机回归与上文有限设备验收分别记录，不能据此扩展为未执行的长稳或全部负载验收。

## 当前速度参数依据

CO5300原厂手册第107页要求写周期≥20ns、时钟高/低各≥6.5ns。选择48MHz，周期20.83ns，CS建立配置1周期；现有资料不支持将本模组80MHz视为安全工作点。本机IDF6.1/S31原始分频函数计算40→40、48→48、50→40MHz，见`tmp/display-clock-audit.log`。代码计算不是示波器测量。

48MHz四线发送整屏RGB565纯像素约19.20ms，40MHz为23.04ms；均未包含命令、渲染、调度或TE等待，不能据此声称满屏60fps。文件列表实际脏区92,208px，48MHz纯像素约7.68ms。当前源码采用双20行PSRAM绘图缓冲与单块内部DMA镜像，资源与设备验证边界见前文。触摸I2C维持400kHz；8ms软件轮询不代表触摸芯片物理扫描率。真实LVGL在8ms/2ms变体下保留按住、拖动、松手、错误消费与100次点击语义；XIP已获用户顺滑反馈，DMA镜像也已获本次文件滑动与亮度拖动的实机确认，长稳和信号质量的进一步测量仍按前述边界保留。
