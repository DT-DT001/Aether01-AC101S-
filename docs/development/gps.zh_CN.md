# 卫星定位（AC101S 版）

桌面“定位”应用读取沃进 VG7669T160N0MA（AT6558R）的真实 NMEA0183 数据。
默认关闭；不会在开机、进入页面时自动输出 5V，也不会自动改写 GPS 配置或系统 RTC。

## 接线

用户已确认，TX/RX 标签是 GPS 模块端的方向，而非 MCU 端。

| ESP32-S31 | GPS 模块 | 用途 |
| --- | --- | --- |
| GPIO37 | ON/OFF | 开漏控制：拉低休眠，释放后由模块内部上拉进入工作 |
| GPIO38 | 1PPS | 输入，统计上升沿；PPS 不等于已有有效定位 |
| GPIO39（MCU RX） | TXD | 接收定位数据，默认 9600 / 8N1 |
| GPIO40（预留 MCU TX） | RXD | 当前不发送配置命令，保持无上下拉输入，避免断电回灌 |
| USB 输入 / 免 CC OTG 共用的 5V | VCC | 模块电源；与主板共地 |

模块供电为5V，串口和控制信号是3.3V电平，不能把5V接到GPIO。
引脚定义集中在 `components/board_config/include/aether_board_pins.h`。

## 启停与电源保护

1. 点击“开启定位”后，后台先判断外部USB输入。以有效VBUS输入为准：电池已充满、不再显示充电时，只要USB输入仍有效，也不启用OTG。
2. 外部供电模式只申请独立的输入ADC测量租约；不启动USB Host、不切换USB路径、不改CC/BOOST/充电配置。输入ADC至少等待1秒并取得两次间隔20ms的4.75–5.5V有效样本，才安装接收串口、启用PPS、释放ON/OFF。
3. 仅在确定没有可直接使用的外部输入时，申请既有TG29免CC手动OTG会话，保留角色、温度、BOOST、RBFET和实际输出电压验证保护。PMIC读取错误、未知状态、输入过压等错误不会回退为强开OTG。
4. 供电不就绪或中途异常时停止定位，不自动反复重新送电。电源来源改变（如拔掉输入）后先安全停止，排查或完成插拔后手动重新开启，再重新判源。
5. 点“停止定位”或离开页面：ON/OFF拉低、停止PPS、删除本应用的UART、取消RX内部上拉，然后仅释放自己持有的输入ADC或OTG租约。ADC恢复失败时保留owner并重试，避免影响之后的供电会话。
6. 电池模式下，本应用从关闭状态打开的OTG会由它关闭；原本由用户开启的手动OTG只借用，退出定位不会误关。用户主动关闭OTG会让该模式下的GPS停止，旧租约不能关闭后来开启的新会话。外部供电退出不关闭USB充电输入。
7. 关机流程先发出GPS取消请求，再等待GPS/电源租约有界清理。普通息屏仍保持当前页面定位，返回/退出定位或关机才停止。

电池模式的免CC接口同时使用USB Host，不只是纯5V开关，会占用USB总线/选择路径。
该模式不能同时使用电脑虚拟U盘；下载/调试连接也可能受到路径切换影响。
外部供电模式不占用USB Host，可保持电脑调试连接；GPS不主动退出电脑虚拟U盘。
GPS退出后沿用原有供电管理，仅释放自己持有的资源。

## 页面与数据

- 天空图：北上、东右；卫星位置来自GSV的方位角/仰角，缺少几何信息时不画点。
- 绿色为GSA报告参与定位的卫星，蓝色为报告有效信号强度的其他卫星，灰色为可见但未报告有效强度。
- 显示参与/可见卫星、定位模式、HDOP、PPS、供电，以及经纬度、海拔、速度和UTC。
- 向下滚动查看最强16颗卫星的C/N0与协议诊断。HDOP是无量纲几何因子，不是米级误差。
- 定位/时间信息5秒无更新即失效；卫星图/GSA集合15秒过期。失效位置显示“--”，不会当作实时坐标继续显示。
- 支持RMC、GGA、GSA、GSV；逐句校验XOR，按星座和信号组装完整GSV轮次后发布，多信号卫星去重。
- 若混合星座GNGSA既没有systemId、也不能唯一确定卫星所属系统，不猜测绿色“参与定位”标记；GGA报告的参与数量仍可正常显示。
- 当前仅展示GNSS时间；不进行RTC自动校时、地图下载、路线导航或轨迹保存。

## 实机验收

1. 先不接GPS，确认开机没有自动启用OTG；默认状态是“未开启”。
2. 接线/共地正确后先插着电脑/充电器打开定位，确认来源为“USB输入”、5V已就绪且没有OTG/Host启动或调试路径切换。充满电时也应走同一路径。
3. 将陶瓷天线朝向开阔天空。首次搜星可能需要数十秒，室内不能保证定位。
4. 查看NMEA计数增长、真实卫星点/C/N0、参与数量及有效经纬度；PPS计数单独观察。
5. 停止数据或遮挡天线，确认过期后不继续显示旧位置为有效；移到开阔处应能重新定位。
6. 再停止定位、拔掉外部输入，以电池供电重新开启，确认“OTG输出”。测试开始后立即停止、离页、重复进入、用户原先已开手动OTG、手动关闭OTG及关机。电源插拔应安全停止且不自动重启。
7. 退出后检查GPS休眠、GPIO39/40无内部上拉；仅关闭GPS拥有的OTG会话。

主机回归覆盖协议、OTG租约与界面，不代表已通过实板接收、PPS电气时序、供电纹波或射频环境测试。

### 2026-11-21 实机记录

- AC101S板，COM40，ESP32-S31 rev0.0；应用区烧录校验成功，分区表与工程一致，保留NVS及资源分区。
- 电池已充满但USB仍接入：`VBUS_good=1, charging=0, done=1`，正确选择USB输入；没有启动USB Host、BOOST或切换调试路径。
- 临时USB输入专用测试运行40秒：输入约5.05V，收到384条校验通过的NMEA、0条校验错误，报告过2～3颗可见卫星；结束时安全停止返回ESP_OK。
- 此次未取得有效位置，PPS计数为0，不能据此认定户外定位或PPS电气链路已通过；纯电池OTG路径已通过主机回归，尚需拔线实板验收。
- 临时测试仅在显式CMake参数`-DAETHER_GPS_DIAGNOSTIC=ON`时编译；自动测试阶段禁止OTG回退。正常交付必须设为OFF，开机GPS保持关闭，由页面按键启动。

### OTG超时反馈后的追加实测

- 窗边USB输入专用测试连续300秒：2994条有效NMEA，校验失败与格式错误均为0；输入5.052～5.062V；最高5颗可见卫星、C/N0最高30dB-Hz。
- 接收机原始RMC持续报告V，GGA持续报告quality=0且无经纬度；300秒结束时未定位、PPS=0，故本次定位验收不通过。此结果不能当作已验证定位或PPS正常。
- 诊断版会记录RMC/GGA/GSA原文（仅本地串口）、首次定位时间、连续定位与近期PPS。仅连续定位至少10秒且有近期至少3个PPS才提前结束成功。
- 自动测试完成并成功清理后才放行用户手动电池GPS测试；随后每5秒打印OTG缓存与最后活动GPS历史快照，不自动重启GPS或OTG，不写RTC/NVS。
- 电池OTG复现流程：拔USB，手动开启免CC OTG，等待结果，关闭OTG并等待5秒，保持不关机/不复位，再接USB读取历史故障。必须按phase区分CC配置、角色等待、开启输出及测压验证；日志使用同次失败快照，不以插线后测量替代。

### 停止定位后无法重新开启OTG（已替代的CC重装试验）

- 追加快照确认：GPS已到ERROR且requested/active为0，Host已OFF且cleanup_pending=0；GPS上一活动快照来自OTG输出，收到344条有效NMEA。此现场没有GPS清理仍占用资源的证据。
- 后一次失败为TIMEOUT，CC原始E7=0x40（按手册低4位为DISABLE）、R19=0x06、R13=0、C0=0x03。VBUS ADC未使能，故显示残留的5134mV是上一有效读数，不能当作本次故障电压。
- 每个新的source epoch强制重装CC配置并重新计算角色等待截止时间。手动开启在输出已验证关闭后执行CC检测disable、配置DRP、再enable，并逐步检查取消状态；不改变外部输入拒绝、低压预检或升压测量条件。
- 这是针对实片CC-state0现象的配置重装验证，手册没有承诺此顺序可复位内部FSM；恢复效果需以实机反复开关结果为准。
- 主机回归：TG29 64组、OTG桥57组、GPS服务46组通过ASan/UBSan；GPS生命周期回归不重新创建task/parser，覆盖故障清理后再定位和停止。
- `-DAETHER_GPS_DIAGNOSTIC_PASSIVE=ON`仅在诊断构建内生效：开机不自动定位、不停止用户GPS，只记录缓存，便于连续电池测试。

### 真正免CC模式修复

- 配置重装试验后仍复现。第二次实机历史故障快照为REG0B=0x0C、E3=0x13、E7=0x40，R19=0x16、R13=0x01、C0=0x07，VBUS原始值5134且有效。说明软件在5.134V输出正常时，仅因CC-state变成DISABLE便触发INVALID_STATE并停机。
- 手动模式改为显式关闭CC检测及CC端口；E7是失活状态机的历史信息，只用于诊断，不再决定手动供电。自动OTG仍要求CC检测开启并检测到ATTACH_SRC。
- 手动源仍需完整快照、明确许可、无外部输入、至少1秒及两次不高于800mV的VBUS预检，以及BOOST/RBFET和4.75～5.50V实测验证；欠压、温度、电流限制与取消门控保持。
- 纯电池且BOOST/RBFET关闭、无其他资源owner时，没有VBUSGOOD应交给独立手动预检，不得仅因CC-state为0便把GPS启动挡在外部输入分支。实际输入存在时仍按外部输入租约验收。
- 被动诊断保留最近一次已验证输出和有效测压上升沿计数`verified_runs`。该计数属于缓存上升沿，需结合Host状态与人工开关步骤确认次数，不能把缓存过期后的恢复自动当作新会话。
- 真正免CC分支回归：TG29 68组、OTG桥59组、GPS服务46组通过。主机模拟覆盖多轮超过60秒的5.134V输出和不同历史E7状态，不代表已取得新的实板持续运行结果。
- 修复后实板反馈不再超时。保留记录显示5次有效测压上升沿，最近一次VBUS=5132mV有效，REG0B=0x04、E3=0x10、E7=0x41，证明检测/端口关闭时，历史E7状态不再阻止正常供电；测试结束Host OFF、cleanup_pending=0且manual_failed=0。
- 这轮最后GPS活动快照为164条有效NMEA、0校验/格式错误，3颗可见、0颗参与、未定位/PPS=0；最后一次会话不能代表此前所有会话，仍需独立验证真实定位。
- 已通过COM40恢复正常固件，两个GPS诊断选项均OFF。应用镜像SHA256为`4CF67E8465744445E6431A64F42D850AA1674A17AC1808BD84E58178EB98849D`，烧录校验成功；25秒启动观察通过，GPS默认OFF、19个应用就绪、未启动临时诊断。仅更新0x10000应用区，保留NVS及资源。
