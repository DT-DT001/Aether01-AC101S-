# Aether01 设备验收步骤

更新日期：2026-11-07。

本表用于验证实际 AC101S 版以太01。按待测硬件和固件版本执行项目，记录观察结果和复现条件。

## 准备与启动

1. 记录板号、PCB修订、芯片完整型号、供电方式、电池状态、IDF版本、固件SHA-256、匹配ELF、分区表以及串口日志。当前正常版固定产物位于 `build/releases/video-memory-balance-release/`，核对清单后使用匹配 BIN/ELF/分区表；历史 `build/Aether01-full.bin` 不代表当前代码。
2. 按最新接线确认显示/触摸：QSPI CLK12、CS10、D0/1/2/3为11/13/14/9，LCD_RST15、TE8、AVDD_EN17；触摸SCL18、SDA19、INT7、RST16。确认三路I²C分别用于系统、音频、触摸。
3. 当前代码仍将传感器电源按ALDO2 3.3V常开策略处理；将传感器改接RTC_VCC或调整中断二极管后，先核对供电和接口电平与固件策略，再做设备验收。
4. 验证系统I²C电气与供电：历史720b与62ec启动记录GPIO0/1空闲为高、TG29 `0x34`探测及DCDC2回读成功、PCF85063 `0x51`应答。每个新镜像仍应记录实际启动，测上拉端、ALDO2/RTC供电和信号裕量，不把数字读高/一次应答当作完整电气认证。早期联调曾拆除传感器，当前按实板装配核对；地磁已从构建排除，QMI8658A/DPS368缺失须显示错误，装回后另验地址、供电和数据。
5. 首次启动确认ESP32-S31目标、32MiB PSRAM、200MHz自检成功、TG29回读及显示初始化成功。无PSRAM降级掩盖、反复复位、看门狗或堆损坏日志。未进入主页时保留首个错误及故障现场，不以重复烧录代替根因定位。
6. 检查中文字、图标、屏幕边缘、触摸坐标与方向。按钮按住100ms以上时不得提前生成松手/点击，真实松手只点击一次；持续拖动音量/亮度滑条、滚动长列表，不能在滑动中点击子项。单独验证ID0释放及双点的一指松手/另一指保持。分别验证息屏时触摸和 BOOT/用户键均不唤醒。通过电源键唤醒时，已按住的触摸必须消费到真实松手，不能触发底下应用。通信错误恢复后，原来被取消的持住手势同样不能误点击。
7. 反复点击和滚动后检查文字是否变斜/损坏，记录GPIO8 TE实际频率及同步、超时降级诊断；只有初始化日志不算同步通过。按[显示窗口与TE验收](display-runtime.zh_CN.md)检查局部窗口、息屏后新边沿、缺失信号降级与实际撕裂，必要时对照TE/CS/CLK波形；首块TE同步不保证整帧无撕裂，TE频率也不等于媒体可见帧率。

## TF 素材

准备FAT32和exFAT TF卡，覆盖MBR及GPT分区；优先使用用户报告的32GB GPT/FAT32卡验证修复，保留原分区和数据。旧FatFs的 `FF_LBA64=0` 无法扫描GPT，新版使用工程内覆盖组件启用GPT。分别测试挂载、中文目录读取、媒体读取和录音写入，记录卡型号、分区起始扇区和错误码；主机夹具通过不等于实卡通过。另备空卡、损坏/不支持格式文件、长中文文件名和多级目录。当前选择保留FAT32/exFAT读写，不引入GPL依赖，NTFS不在支持范围；未知文件系统不得被自动格式化。

| 目录 | 验收素材 |
|---|---|
| `/Music` | PCM16 WAV：8/16/22.05/44.1/48kHz、单/双声道；MP3的CBR/VBR样本；空文件、截断文件、不支持的24bit/压缩WAV。 |
| `/Books` | UTF-8、GBK/CP936、带BOM的UTF-16LE/BE TXT：短篇/空文件/数MiB长篇、CRLF/LF、中英文混排、跨块字符/代理对及覆盖内生僻字；另备无BOM歧义样本和无BOM UTF-16验证手选，截断/坏码验证诊断。GB18030四字节扩展/UTF-32不作支持项。 |
| `/Video` | raw MJPG/MJPEG、经典单RIFF MJPEG-AVI的25/29.97/30FPS带帧号样本；240×240、480×480及其他宽高均为16倍数的baseline JPEG帧。MP4使用非分片constrained-baseline avc1 H.264与AAC-LC，先验收320×240/15fps及已转换的用户素材；另备空文件、截断、渐进式JPEG、非法尺寸、非MJPEG AVI、AVIX续段、Main/High/B帧等不支持MP4及自动超30FPS素材。 |
| `/ROMs` | 用户合法提供的NTSC iNES 1.0 ROM，覆盖实际需要且内置核心已实现的Mapper、带SRAM与不带SRAM、损坏ROM；另备PAL-only/NES 2.0验证明确拒绝。固件不附带ROM。 |

将部分素材放在卡根目录验证默认回退扫描，另放入子目录验证文件浏览器分发。

文件系统启用64位长度不等于应用支持超大文件。使用夹具验证达到或超过2GiB的文件大小、定位和追加在S31的32位文件位置/stat接口返回 `EOVERFLOW`，不能变成负长度、截断回卷或覆盖已有文件；本轮不把>2GiB播放或录音列为支持项。

## 逐项功能

| 应用 | 操作 | 通过标准 |
|---|---|---|
| 设备状态 | 运行中打开状态页，滚动到内存/TF信息；插拔卡、制造可恢复的外设通信失败再观察。 | 时间持续更新，TF状态真实变化，PMIC失败显示错误而非固定OK；PSRAM/内部堆数值合理，无滚动截断导致信息不可达。 |
| 时钟与日期 | 设置已知时间，跨分钟观察；修改月份/年份，测试2024-02-29与2025-02-29、4月31日；保存后断开主系统供电再上电。 | 非法日期被限制/拒绝，星期正确；保存期间防止重复提交，成功须经过RTC回读；RTC电源保持时重启时间连续。I²C失败显示失败且页面仍能操作。 |
| 运动与姿态 | 六面静置、慢转和快速移动；查看加速度、角速度、合加速度、横滚/俯仰。 | 各轴随物理方向变化，静止合加速度接近重力，姿态符号与板轴一致；动态提示不将重力姿态当精确运动姿态；断连显示错误。 |
| 气压与高度 | 对照已知气压/温度；改变海平面参考气压，设置相对高度零点，改变高度；重进页面/重启。 | 参考海压影响估算海拔并能持久保存，相对归零后接近0；最低/最高值更新。海拔按气压模型估算，天气变化不被当作算法失效。无效数据不显示假正常。 |
| 音乐 | 从曲库选中文文件名歌曲，播放、暂停/继续、停止、上一首/下一首；拖动进度、音量0/5/50/100%；测试三种模式和自动播完换曲；播放及启动中离页，再返回或切视频/NES。 | 真正改变声音/文件/进度，暂停停止前进，继续不从头开始；静音无可闻输出且有明确状态，重采样无明显变调/速度错误。离页后异步停止并释放decoder、codec、FILE、存储租约及曲库，不能继续出声或自动换曲；清理完成才可启动下一媒体，音量/模式仍可恢复。坏文件报错后可换歌，不死循环跳过。 |
| 视频 | 列表选片、暂停/继续、停止/重播；验证控制层3秒隐藏、触摸唤出及MP4拖动跳转。MJPEG测试自动→24→30→10→15→自动和240/480素材；播放/启动中退出再进其他媒体。 | 真实画面、正确方向/色序/比例；自动保留原始微秒节拍，暂停排除活动时间，暂停中拔卡明确结束报错。离页关闭音频、解码、文件、存储租约和帧引用，新页面不得显示旧帧。目标FPS与产帧、LCD完成分别记录，不作为性能承诺。MP4受限编码、AAC-LC及真实跳转按格式范围验收；分别向前/后跳、暂停中跳转后继续、连续替换目标。首帧/音频就绪后应连续按节拍播放，不因音频重开持续丢帧；记录跳转瞬时等待与后续持续卡顿，不能混为同一结果。AVI音轨/OpenDML仍不支持。 |
| 录音机 | 在FAT32/exFAT上分别开始录音、暂停/继续、停止保存、回放，录音中离页或拔卡；保持板载/USB输入选择与显示一致。 | 离页异步停止并尽力完成WAV头/文件同步，正常保存后时长与声音正确；写入失败明确报错且保留可恢复文件，不误录另一音源。录音与音乐/视频/NES互斥，文件和存储租约释放后才允许交接。 |
| 小说阅读 | 用四种编码分别选书、切16/24字号/主题、前后翻页、跳100%末页、退出重开再上一页；手选编码并重启；长篇读过32KiB，GBK长段定位中返回/拔卡。 | 使用提供字体且覆盖内文字可读；记录实际编码、本页缺字/本块坏码；有效样本应为0，不把未知字节伪造为汉字。翻页不丢字/重复/拆码点，源文件字节位置不因转码和字号变化错移，旧书签/手选编码恢复正确；任意定位可取消且文件/缓冲释放，空书/坏码有明确反馈。 |
| 文件 | 浏览根目录、中文/深层目录、上一页/下一页、返回上级、刷新；分别点TXT/MP3/WAV/MJPEG/NES及其他文件。 | 目录导航真实，支持的文件打开指定文件而非第一份文件；不支持的格式显示大小和提示。大目录分页/索引上限明确，路径不过界；异步返回不会修改已经离开的页面。 |
| 反应力小游戏 | 开始、连续点击、暂停数秒后继续、到时、重开；在最后一刻点击；退出重进/重启。 | 未开始/暂停/到时不计分；倒计时按单调时间计，不受UI延迟累积漂移；圆点不遮挡状态或按钮；最高分后台保存并恢复。 |
| NES | 从列表选择指定NTSC iNES1.0 ROM，用USB标准键盘/通用HID手柄测试方向、组合键、A/B、SELECT/START、暂停/继续及重启。游戏中用默认 Esc 退出，并验证加载中和游戏中均可长按用户键 2 秒回桌面。重复进入和退出后切换音乐或视频，测试声音及SRAM保存，在可控副本上注入短读、短写、同步失败和保存时拔盘。 | 只显示纯游戏画面，无虚拟按键。亮屏时每次达到 2 秒的长按只触发一次退出，抖动和过期页面事件不会重复触发。退出后停止CPU/PPU/APU供料并释放ROM、codec、文件/存储租约及帧引用；清理失败保留原所有权，成功前不启动下一媒体。暂停不推进、继续恢复音频；坏ROM/不支持Mapper明确失败，旧SRAM读取失败时禁止覆盖；新存档未完整同步前旧文件/备份可恢复，失败明确报告且会话正常释放。逐ROM验收，不声称所有Mapper兼容。 |
| NES按键映射 | 设置→NES按键映射，检查11个动作各两键；修改方向/A/B/选择/开始/退出/暂停/重启，测试取消绑定、冲突、恢复默认、退出重进及重启。 | 默认方向键/WASD、Z/X、Shift选择、Enter开始、Esc退出、P暂停、R重启。映射立即影响HID键盘，旧键不继续触发被替换的动作；冲突被拒绝且不会残留半更新。设置经NVS保存恢复，活跃媒体期间允许延后Flash提交，保存失败明确显示并可重试；手柄状态不因键盘改键被清除。 |
| 设置 | 立即息屏和自动息屏后触摸、拖动或按 GPIO61 BOOT/用户键，确认均不唤醒。用 TG29 电源键恢复，覆盖 NES 加载、运行和手动暂停。调整亮度、保存重启并注入失败。 | 待机保留显示电源和连接，暂停界面和前台会话，正常播放的音乐继续。TG29 按下即可唤醒，界面恢复原位置和亮度。已按住的用户键与触摸消费到真实松手，旧0%设置不能隐藏冷启动界面。 |

| OTG U盘与手柄 | 开OTG接标准U盘，在文件浏览切“USB U盘”列目录并打开素材；读取中拔出、关闭OTG、重新插入。另接通用HID手柄测试方向轴、四/八向帽、按钮组合及拔出。 | 首盘FAT32/exFAT/受支持GPT真实挂载，未知格式不格式化；失效租约阻止新操作，失败卸载保留owner而非提前释放。TF与USB同时挂载不占用同一驱动槽；用户取消转换后不复活部分卸载的卷。手柄方向与物理一致，空轴中性且不丢按钮，拔出清除按住状态。当前不验收Hub、XInput或私有协议。 |

## 热插拔和资源交接

1. 分别在音乐播放/暂停、小说读取/翻页、视频解码、NES运行、目录扫描和挂载过程中拔卡；每种至少重复20次。期待播放器/文件任务关闭使用者、界面报错可返回、卡卸载后BLDO1关闭。记录卸载耗时、电压、当前文件操作及错误日志。
2. 插卡后重新打开或刷新列表，确认重新挂载后可继续使用；卡未就绪时点击播放/阅读不能使UI卡死。使用空卡和坏文件不应引起重启。
3. 音乐播放时离页到阅读、目录、传感器或设置，确认随离页关闭；随后进入视频或NES，反向也测试。清理完成前新媒体保持门控，不能有两个任务同时驱动AC101S、两个文件会话继续读卡，或旧页面帧覆盖新页面。注入codec停止/释放超时后，原所有者和租约须保留至后台重试成功，不能提前释放仍在使用的缓冲。
4. 快速连续切换14个入口至少100轮，并反复执行“媒体启动中立即返回”和“NES按用户键退出后立刻进入音乐/视频”。检查异步取消、文件/解码/曲库及帧内存释放和存储租约归零；稳定管理任务和等待通知的控制任务可以保留。后台旧结果不得更新新页面，返回后按钮不得失灵，反复切换后不能持续变慢。

## Flash 与内存

1. 确认启动识别的是W25Q512JV并启用了Winbond专用驱动，记录JEDEC ID、实际容量和驱动日志，以及末4KiB内16字节只读探测结果。该探测不擦写，一次成功不能证明无地址别名或所有扇区可写。此前generic驱动的16MiB限制不能凭配置消除验收。
2. 由专门硬件测试程序在确认未占用的数据区域验证16MiB边界上下及接近64MiB边界的擦写/读回，并校验低地址未被地址回卷覆盖；对齐扇区并记录测试区间。不得直接对现有NVS、应用、书签或用户数据做破坏性测试。
3. 阅读书签使用独立256KiB `reader_nvs`。分别保存多本书，重启后检查位置独立；覆盖/截短书文件后应将旧位置限制在新文件范围内。
4. 主机回归与静态size不包含所有运行时分配。记录媒体/阅读/目录加载时的内部堆、最低堆、最大连续块、PSRAM和任务栈水位，确认异步退出完成后回到稳定基线；共享管理器常驻占用不等于会话泄漏，但decoder、codec、FILE、存储租约、曲库和媒体帧必须释放，反复切页无持续增长。

## 错误恢复与长稳

- 在具备可控故障夹具的条件下模拟系统I²C超时、触摸通信失败、NVS提交失败、挂载失败和播放器坏文件。预期是有界等待、错误状态、退避重试或明确停止，不是abort/复位循环。强制关机或MCU崩溃可能绕过软件清理，不能据正常关机测试宣称掉电接口已得到硬件隔离。
- 运行24小时混合负载，再运行72小时长稳：循环播放/阅读/切页/息屏唤醒，周期插拔TF并记录每分钟健康日志。记录复位原因、看门狗、栈最低水位、堆完整性、最大连续块、输入延迟与实际帧率；存在持续泄漏或无恢复错误即为未通过。
- 显示刷新和触摸响应应实测：分别记录视频producer、NES emulated/generated、三缓冲交接/覆盖/等待以及LCD最后一块传输完成。LCD完成包含局部UI更新，不能当作唯一视频帧或面板扫描率；LVGL的16ms调度周期和目标30FPS均不是测量值。
- 按[多媒体定量长测用例](media-runtime.zh_CN.md)执行各源节拍/分辨率10分钟、每个所需Mapper代表ROM30分钟、暂停/退出100轮、各状态拔卡20轮和24/72小时混合负载。预算与记录方法为建议验收条件，不表示已经达到；保存带帧号素材和外部输入至可见响应测量，不能用10秒日志的最近耗时冒充全部帧的p95/p99。

## 未实现的验收项

当前没有完整实现“PCF85063配置闹钟和清中断 → TG29关闭MCU 3.3V → RTC事件经硬件唤醒TG29 → MCU冷启动”的整机关机定时唤醒流程，不能作为通过项。3秒软件关机已有传感器优先休眠、读回确认及有界非关键清理路径；仍须在实际常供电QMI8658A/DPS368上捕获读回和测量关机电流，验证失败时不跳过必需的传感器休眠。TG29的8秒硬件强制关机保留，不能保证其执行软件清理。
